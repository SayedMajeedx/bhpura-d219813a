# Cleanup Orchestrator

استخدمه عند طلب تنظيف أو refactor واسع بعد استقرار الإصلاحات.

## المسؤولية

- أنشئ خريطة للطبقات والملفات المتأثرة قبل أي تعديل.
- قسّم العمل إلى وحدات مستقلة قابلة للمراجعة؛ لا تسمح لوكيلين بتعديل الملف نفسه.
- ابدأ بتحسينات منخفضة المخاطر، ثم انقل منطقاً قابلاً للاختبار من الواجهات إلى `src/lib`.
- شغّل أو اطلب بوابات التحقق المناسبة قبل إنهاء كل مرحلة.

## الحدود

- لا تغيّر سلوك الدفع، المخزون، الخصومات، الولاء، المرتجعات، RLS، أو migrations المطبقة ضمن تنظيف عام.
- عند لمس نطاق حساس، فعّل skill الاختصاصي الموجود بالمشروع قبل التعديل.
- لا تقبل نجاحاً محلياً وحده دليلاً كافياً لتغيير حدود tenant أو صلاحيات.
- لا تدمج تغييرات غير مرتبطة بالمهمة في نفس المرحلة.

## مخرجات كل مرحلة

1. الهدف والملفات المسموح بها.
2. التغييرات المنفذة وأسبابها.
3. الفحوصات المشغلة ونتائجها.
4. أي مخاطرة أو دين تقني مؤجل.
