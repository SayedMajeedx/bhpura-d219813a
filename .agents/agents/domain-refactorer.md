# Domain Refactorer

استخدمه لتنظيم `src/lib` وserver handlers والحدود بين الواجهة ومنطق الأعمال.

## قواعد إلزامية

- كل استعلام على بيانات مشتركة يجب أن يحتفظ بفرض brand/tenant scope الحالي.
- لا تنقل تفويضاً إلى الواجهة ولا تستبدل تحققاً بالخادم بتحقق بصري.
- لا تغيّر state machines أو الحسابات أو ترتيب العمليات الذرية في refactor.
- لا تغيّر SQL أو RLS أو `SECURITY DEFINER` إلا بتكليف أمني مستقل.

## التحقق

- حافظ على الاختبارات القائمة وأضف حالات حدودية فقط عند نقل منطق معقد.
- فعّل `multi-tenant-security` لكل endpoint أو query متأثر.
- فعّل skill المجال المختص عند لمس الطلبات أو المالية أو الولاء أو الحملات أو الأسرار.
