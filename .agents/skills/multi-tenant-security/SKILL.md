# عزل بيانات المستأجرين والأمان (Multi-Tenant Security)

## متى تستخدم هذا الـ skill
- أي استعلام جديد لقاعدة البيانات (query, ORM call).
- أي API endpoint جديد أو معدّل.
- أي كود يتعامل مع session، JWT، أو صلاحيات مستخدم.
- أي feature يسمح برفع ملفات أو مشاركة روابط (قد تكشف بيانات tenant آخر).
- قبل أي عملية نشر تمس الـ backend أو schema.

## خطوات الفحص الإلزامية

### 1. فحص tenant_id في كل استعلام
لكل query يمس جدول بيانات مشترك بين المستأجرين (orders, customers,
products, invoices...)، تأكد إنه:
- يحتوي شرط `WHERE tenant_id = :current_tenant` (أو ما يعادله) بشكل
  **إجباري وليس اختياري**، ويفضل أن يكون مفروض على مستوى الـ ORM/middleware
  وليس متروك لكل مطور يكتبه يدوياً بكل استعلام (خطر نسيان بشري عالي).
- لا يعتمد فقط على الـ ID الممرر بالـ URL/request بدون تحقق من ملكيته
  لنفس الـ tenant الحالي (IDOR — Insecure Direct Object Reference).
  مثال خطر: `/api/orders/1096` — لازم النظام يتحقق إن الطلب 1096 يعود
  فعلاً لمتجر المستخدم الحالي، مو بس إنه موجود بقاعدة البيانات.

### 2. فحص الملفات والروابط المرفوعة
شعارات المتاجر وأيقوناتها (زي اللي شفناها بإعدادات الملف التجاري) عادة
تُخزن بروابط عامة (public URLs) بمسار يحتوي tenant identifier. تأكد:
- الرابط لا يمكن تخمينه بسهولة (sequential IDs) لتفادي enumeration.
- لا يوجد مسار يسمح لمستخدم يرفع ملف باسم يطغى على ملف tenant آخر
  (path traversal / filename collision).

### 3. فحص الصلاحيات على مستوى الأدوار (Roles)
- تأكد إن كل endpoint يتحقق من دور المستخدم (admin/staff/viewer) وليس
  فقط من كونه مسجل دخول (authenticated ≠ authorized).
- الموظف بصلاحية محدودة (staff) يجب ألا يقدر يوصل لإعدادات حساسة زي
  الملف التجاري، الرقم الضريبي، أو بيانات الدفع، إلا إذا صلاحيته صريحة.

### 4. فحص تسريب البيانات عبر رسائل الخطأ
تأكد إن رسائل الخطأ (error messages) ما تكشف معلومات عن وجود بيانات
tenant آخر، مثل الفرق بين "غير موجود" و"غير مصرح لك"، لأن هذا الفرق
بحد ذاته يسرّب معلومة (إن الـ ID موجود بس يخص حد ثاني).

### 5. فحص الحقول الحساسة الفارغة كخطر امتثال
حقول زي "الرقم الضريبي" و"نسبة الضريبة" إذا تُركت فارغة أو صفر، تأكد
إن النظام:
- ينبّه التاجر بوضوح (لا يصمت) خصوصاً لو الدولة تفرض ضريبة قيمة مضافة
  إجبارية (مثل البحرين 10%).
- لا يصدر فواتير رسمية بدون هذي البيانات إذا كانت مطلوبة قانونياً
  لنوع النشاط والدولة.

## Output المطلوب من الـ agent
1. قائمة بكل query/endpoint تم فحصه، وهل فيه فرض صريح لـ tenant_id.
2. أي endpoint مكتشف فيه احتمال IDOR (اختبر بمعرّف يخص tenant آخر فعلياً
   إذا كانت بيئة الاختبار تسمح).
3. تقرير عن مسارات الملفات المرفوعة وهل قابلة للتخمين.
4. أي حقل حساس فارغ (ضريبي، عنوان قانوني) بدون تنبيه للمستخدم.
