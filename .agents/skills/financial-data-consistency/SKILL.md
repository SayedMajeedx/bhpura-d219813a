# اتساق البيانات المالية عبر الصفحات (Financial Data Consistency)

## متى تستخدم هذا الـ skill
- أي صفحة مصاريف/نفقات، تقارير مالية، أو P&L.
- أي كارت يعرض "إجمالي الإيرادات" أو "تكلفة البضاعة" أو "الربح الصافي"
  خارج صفحة الطلبات المباشرة.
- عند إضافة مصدر بيانات مالي جديد (مثال: ربط مصاريف بمصدر منفصل عن
  جدول الطلبات).

## خطوات الفحص الإلزامية

### 1. فحص التناقض الداخلي بنفس الشاشة (Same-Page Contradiction)
هذا أخطر نوع مكتشف — كارت ملخص بأعلى الصفحة يعرض رقماً (مثال:
"تكلفة البضاعة: 0.000") بينما **نفس الصفحة بالأسفل** تعرض تفاصيل
تناقض هذا الرقم تماماً (مثال: "إجمالي المشتريات المسجلة: 53.950" مع
بنود فعلية موثقة). هذا يعني بشكل شبه مؤكد إن الكارت العلوي يسحب من
مصدر بيانات (query/cache) مختلف تماماً عن الجدول التفصيلي بنفس الصفحة.
لكل صفحة مالية:
- حدد مصدر البيانات (query) لكل كارت ملخص على حدة.
- قارنه يدوياً بمصدر بيانات الجدول التفصيلي بنفس الصفحة.
- أي فرق = باگ حرج (Blocker) يجب حله قبل أي شيء آخر بهذي الصفحة.

### 2. فحص التطابق عبر الصفحات (Cross-Page Reconciliation)
قارن نفس المقياس المالي (الإيرادات، عدد الطلبات، القيمة الإجمالية)
كما يظهر في:
- لوحة التحكم الرئيسية (Dashboard).
- صفحة الطلبات والفواتير.
- صفحة المصاريف/التقارير المالية.
لو صفحة "الإيرادات" تظهر بقيمة مختلفة تماماً (مثال: 0 مقابل 78 د.ب.
بصفحة أخرى)، وثّق أي المصدرين هو "مصدر الحقيقة" (source of truth)
الصحيح، وحدد سبب انقطاع التزامن (sync) بين الوحدتين — عادة يكون:
- الصفحتان تستعلمان من جداول مختلفة (orders مقابل ledger منفصل)
  بدون job تزامن (sync job) بينهما.
- فلتر فترة زمنية مختلف بصمت بين الصفحتين (مثال: صفحة تحسب "الشهر
  الحالي" فقط والثانية "كل الوقت") بدون توضيح هذا الفرق للمستخدم.

### 3. فحص التصنيف المحاسبي (Accounting Classification)
تحقق من منطق تصنيف المصاريف بين COGS (تكلفة مباشرة مرتبطة بوحدة
مباعة) و OpEx (مصاريف تشغيلية ثابتة). بنود مثل مواد التغليف قد تُصنَّف
بأي منهما حسب سياسة المحاسبة المتبعة — تأكد من أن التصنيف قابل
للتخصيص من قبل التاجر/المحاسب، وليس مثبتاً (hardcoded) بمنطق قد لا
يناسب كل الأنشطة التجارية.

### 4. فحص فلاتر الفترة الزمنية الصامتة
أي جدول يعرض "لا توجد بيانات لهذه الفترة" بينما بيانات فعلية موجودة
بمكان آخر بنفس الصفحة (بتاريخ داخل نفس الفترة المفلترة ظاهرياً)، تحقق
من منطق الفلتر (اليوم/الأسبوع/الشهر) وتأكد إنه يُطبَّق بشكل متسق على
كل عناصر الصفحة، لا على جزء منها فقط.

## Output المطلوب من الـ agent
1. لكل صفحة مالية: خريطة مصادر البيانات لكل كارت/جدول، وأي تناقض
   داخلي مكتشف بنفس الشاشة مع تحديد أي مصدر هو الصحيح.
2. جدول مقارنة لنفس المقياس المالي عبر الصفحات المختلفة (Dashboard،
   الطلبات، المصاريف) مع تحديد أي فروقات وسببها المحتمل.
3. تقرير عن منطق تصنيف COGS/OpEx وهل هو قابل للتخصيص.
4. أي فلتر فترة زمنية يُطبَّق بشكل غير متسق داخل نفس الصفحة.
