# التحقق من دقة صفحة التقارير (Reports Integrity Check)

## الهدف
التأكد إن كل رقم بصفحة التقارير صحيح رياضياً ومتسق مع باقي الأرقام،
وكشف أي بيانات ناقصة أو غير مصنّفة قبل ما تصير مصدر قرار خاطئ.

## الخطوات

### 1) افتح صفحة التقارير واستخرج القيم
- اذهب إلى: `التقارير > نظرة عامة` (Reports > Overview).
- التقط القيم التالية كأرقام (مو كنص/صورة فقط):
  - الخصومات، عمليات البيع المكتملة، صافي مبيعات المنتجات،
    قيمة المبيعات المكتملة، المصروفات (وتفصيلها: يدوية + رسوم + عمولات)،
    ضريبة القيمة المضافة، الشحن المحصل، صافي الربح التشغيلي،
    هامش الربح، مجمل الربح، صافي الإيراد بعد الاسترجاع.
  - جدول "صحة بيانات التكلفة": تكلفة البضاعة المعروفة، تكلفة المنتجات،
    تكلفة تغليف الطلبات، عناصر بلا تكلفة، عناصر بلا رابط منتج،
    عناصر مكتملة بتغليف صفري، قيمة المبيعات المتأثرة.
  - جدول "تفاصيل التحصيل": المبالغ الجزئية، المبالغ المسترجعة،
    مبيعات الحاضنات، عمولات الحاضنات، مستحقات الحاضنات،
    طلبات مجانية مكتملة.
  - أي شارة تحذير ظاهرة (مثل "يتطلب المراجعة").

### 2) أعد حساب العلاقات المتوقعة وقارنها بالمعروض
تحقق من كل معادلة، ولو فيه فرق أكبر من 0.01 د.ب. سجّله كـ "تناقض":

| المعادلة | الأطراف |
|---|---|
| مجمل الربح = صافي الإيراد − تكلفة البضاعة المعروفة | |
| هامش الربح % = مجمل الربح ÷ صافي الإيراد × 100 | |
| متوسط الطلب = صافي مبيعات المنتجات ÷ عمليات البيع المكتملة | |
| **تكلفة البضاعة المعروفة = تكلفة المنتجات + تكلفة تغليف الطلبات** (+ أي بند تكلفة ثالث ظاهر) | ⚠️ هذي المعادلة اللي فيها الفجوة المكتشفة سابقاً — تحقق منها بعناية خاصة |
| المصروفات = يدوية + رسوم + عمولات | |
| صافي المبيعات = قيمة المبيعات المكتملة − الخصومات | |

### 3) اربط كل فجوة رقمية بسببها المحتمل
لو "تكلفة البضاعة المعروفة" أكبر من مجموع تفصيلها:
- تحقق من رقم "عناصر بلا رابط منتج" و"عناصر بلا تكلفة" في نفس الجدول.
- لو فيه عناصر بلا رابط منتج (>0)، هذا على الأغلب هو مصدر الفجوة —
  التكلفة مسجلة على مستوى الطلب لكن مو مصنّفة بالتفصيل لعدم ربطها
  بمنتج محدد.
- اذهب إلى `الطلبات` وفلتر على "بلا رابط منتج" (أو ابحث يدوياً عن آخر
  طلبات ضمن الفترة المحددة) لتحديد الطلبات المسؤولة عن الفجوة بالضبط.

### 4) كرر الفحص لكل فترة زمنية يطلبها المستخدم
- كرر نفس الفحص لو غيّر المستخدم نطاق التاريخ (Date Range)، لأن الفجوات
  ممكن تختلف حسب الفترة.

## المخرجات المتوقعة
تقرير نصي مختصر يتضمن:
1. ✅ قائمة المعادلات اللي طابقت (صحيحة).
2. ⚠️ قائمة الفجوات المكتشفة، مع الفرق بالدينار ومصدرها المحتمل.
3. 🔗 روابط أو أرقام الطلبات المشتبه فيها (إن أمكن الوصول لها).
4. توصية: هل الفجوة تحتاج تصحيح بيانات يدوي، أو مجرد طلبات لسه ما
   اكتمل ربطها بالمنتج.

## قواعد الأمان
- هذا Skill قراءة فقط (Read-Only) — لا تعدّل أي بيانات أو طلبات تلقائياً.
- لو احتجت فتح تفاصيل طلب معيّن للتحقق، لا تضغط أي زر "حذف" أو "تعديل".
