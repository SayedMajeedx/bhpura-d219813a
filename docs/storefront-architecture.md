# Boutq OS — Storefront 2.0 Engine Architecture

وثيقة معمارية مرجعية لمحرك واجهات المتاجر في منصة Boutq OS (نظام التجارة الإلكترونية متعدد المستأجرين لبوتيكات الخليج العربي — مبني على TanStack Start + React 19 + Supabase + Cloudflare Workers / R2).

---

## 1. فلسفة ترقية المحرك والإصدارات (`storefront_design_version`)

صُممت ترقية **Storefront 2.0** وفق مبدأ **"ترقية محرك للمنصة بالكامل، وليس قالباً خاصاً بمتجر واحد"** (Engine upgrade, not a single theme). لضمان استقرار متاجر التجار القائمة وعدم مفاجأة أي تاجر بتغيرات تصميمية غير مرغوبة:

1. **مفتاح الإصدار المعماري (`storefront_design_version: 1 | 2`)**:
   - يتم التحكم بنسخة الواجهة عبر عمود `storefront_design_version` في جدول `business_settings` لكل براند.
   - القيمة الافتراضية للمتاجر القائمة تظل `1` (النسخة الكلاسيكية المستقرة).
   - التبديل إلى `2` يفعّل تلقائياً حزمة مكونات الستورفرونت المتطورة (V2) دون المساس بمنطق العمليات التجارية الحساس (السلة، الدفع، الحسابات، صلاحيات المستأجرين).

2. **التفريع الشرطي الشفاف (Dynamic Dispatch)**:
   - المكونات المتباينة جذرياً (مثل بطاقة المنتج، الهيرو، الفوتر، الفلاتر) تفحص الإصدار بسلاسة وتوجّه إلى V1 أو V2.
   - مثال: في `src/components/storefront/product-card.tsx`:
     ```tsx
     if (settings?.storefront_design_version === 2) {
       return <ProductCardV2 {...props} />;
     }
     return <ProductCardV1 {...props} />;
     ```

## 3. ما يبدأ به متجر كل نشاط (`VERTICAL_DESIGN_PRESETS`)

لكل نشاط تجاري إعدادان تصميميان فقط يطبّقهما النظام فعلاً (`src/lib/brand-templates/design-presets.ts`):

1. **نصف قطر الزوايا (`radius`)**: يكتبه معالج إنشاء المتجر مرة واحدة في `storefront_radius`، ثم يصبح ملكاً للمتجر يغيّره من إعداداته.
2. **شكل صورة المنتج في البطاقات (`productPhoto`)**: يُقرأ عند كل عرض عبر `productCardRatio` ما دام المتجر لم يختر شكلاً بنفسه (`business_settings.product_card_aspect_ratio` فارغ، migration `20261023130000`)، فيتبع المتجر نشاطه (وتغيير نشاطه) حتى يختار. يختاره التاجر من الإعدادات ← بطاقة المنتج وصفحته.

| النشاط                                         | الزوايا    | شكل الصورة                       |
| :--------------------------------------------- | :--------- | :------------------------------- |
| الأزياء، العبايات                              | `0.5rem`   | طولي 3:4 (الملابس تُصوَّر واقفة) |
| التجميل، العطور، المجوهرات                     | `0.5rem`   | مربع 1:1                         |
| المأكولات، القهوة، الهدايا                     | `1.25rem`  | مربع 1:1                         |
| المنزل والديكور                                | `1.25rem`  | عرضي 4:3                         |
| الخدمات                                        | `0.75rem`  | عرضي 4:3                         |
| الإلكترونيات، الرقمية، المطبوعات، المتجر العام | `0.375rem` | مربع 1:1                         |

كانت هذه الأنماط تَعِد أيضاً باسم نمط (`editorial` / `fresh` / `tech`) وشبكة من 4 أو 5 أعمدة وتباعد ونمط بطاقة، ولم يكن شيء من ذلك يُقرأ في أي مكان: حُذفت (`tests/brand-templates.test.ts` يمنع عودتها). أما شكل صفحة المنتج فإعداد مستقل (`pdp_gallery_aspect_ratio`). الاختلاف الأعمق بين الأنشطة هو طريقة الشراء لا الشكل: متجر الخدمات له صفحته الرئيسية الخاصة (`ServicesHome`).

## 4. خط أنابيب الوسائط والأداء الفائق (Media & Performance Pipeline)

تطبق منصة Boutq OS سياسة صارمة للأداء وضمان استجابة سريعة للزوار من مختلف شبكات الاتصال بالخليج:

1. **توصيل الصور عبر Cloudflare Images / R2**:
   - تحويل فوري إلى صيغ WebP/AVIF الحديثة.
   - توليد أحجام مخصصة بحسب أحجام شاشات الأجهزة عبر `cloudflareImageUrl(url, { width, quality })`.
2. **مكوّن `ResponsiveImage`**:
   - فرض أبعاد صارمة بنسبة محددة تجنباً لانزياح التخطيط التراكمي (0 CLS).
   - تحميل صور الهيرو الأولى ذات الأولوية عبر `loading="eager"` و`fetchPriority="high"`.
   - تحميل باقي صور الكروت والقوائم بطريقة كسولة `loading="lazy"` و`decoding="async"`.
3. **مكوّن `OptimizedVideo`**:
   - إيقاف تشغيل الفيديو تلقائياً فور خروجه من إطار الرؤية (ViewPort) باستخدام `IntersectionObserver` لتوفير طاقة أجهزة الجوال واستخدام البيانات.

## 5. محرك الحركة والانتقالات الحركية (Motion & View Transitions)

الحركة في Storefront 2.0 تعتمد كلياً على **CSS الخالص وواجهات المتصفح الأصلية** بدون إضافة أي مكتبة خارجية ثقيلة (0 KB JS Animation Overhead):

1. **كاشف الظهور الانسيابي (`useReveal` Hook)**:
   - مراقبة عناصر الصفحة عبر `IntersectionObserver`.
   - بمجرد دخول العنصر لمجال الرؤية، يُضاف الصنف `is-revealed`.
   - استخدام طبقات تأخير متعاقبة للمنتجات (`sf-stagger-1` إلى `sf-stagger-8` بفارق 40ms لكل كارت).
2. **واجهة الانتقالات الرسومية (View Transitions API)**:
   - تفعيل تنقل سلس بين بطاقة المنتج في القائمة وصفحة المنتج التفصيلية عبر `navigateWithViewTransition` و`getProductTransitionName(product.id)`.
   - عند الضغط على الكارت، تتماهى صورة المنتج وتكبر إلى مكانها المخصص في صفحة PDP بتأثير طبيعي.
3. **احترام تفضيلات الحركة وتقليل الانزعاج (`prefers-reduced-motion`)**:
   - يتم التحقق برمجياً وفي ملفات CSS `@media (prefers-reduced-motion: reduce)` لإلغاء جميع الحركات والانتقالات تلقائياً للمستخدمين الذين يفضلون ذلك، وضمان ظهور المحتوى فوراً بنسبة تعتيم 100%.

## 6. دليل إضافة قسم أو ميزة جديدة إلى الستورفرونت

عند بناء أو إضافة أي مكوّن جديد لواجهة المتجر، اتبع القواعد الإلزامية التالية:

1. **عدم استخدام ألوان Hex ثابتة**:
   - التزم تماماً برموز التصميم الدلالية: `bg-primary`, `text-primary`, `bg-muted`, `border-border`.
2. **دعم ثنائي اللغة والاتجاه العربي من البداية (Bilingual + RTL First)**:
   - يجب أن يدعم كل نص الترجمة عبر دالة `t("نص عربي", "English text")`.
   - استخدام أصناف Tailwind المنطقية للاتجاه: `start-*`, `end-*`, `ps-*`, `pe-*` بدلاً من `left` و`right`.
3. **الحيادية القطاعية للمكونات الأساسية (Vertical-Agnostic Core)**:
   - المكونات العامة المشتركة يجب ألا تحتوي كلمات خاصة بنشاط تجاري بعينه (مثل كلمة "عباية" أو "تفصيل") في الكود الأساسي المشترك، بل تستخدم عبارات فاخرة عامة تناسب كافة الأنشطة، وتُستمد الخصوصية من قوالب الأنشطة `brand-templates`.
4. **الأزرار وتفاعلات اللمس**:
   - استخدام المكون المشترك `<Button>` بمتغيراته القياسية.
   - ضمان أبعاد لمس لا تقل عن 44px للأجهزة المحمولة (`size="icon-touch"` أو `size="icon"`).
5. **إمكانية الوصول (Accessibility WCAG 2.2 AA)**:
   - حلقة تركيز ظاهرة بوضوح عبر لوحة المفاتيح: `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`.
   - تسميات واضحة ومقروءة لجميع أزرار الإجراءات عبر `aria-label`.

## 7. التقاط العملاء المحتملين (Back-in-stock & Newsletter)

- المتصفح **لا يكتب** في `back_in_stock_requests` أو `newsletter_subscribers` مباشرة؛ لا توجد سياسة
  `INSERT` لـ `anon` على الجدولين.
- الكتابة تمر حصراً عبر دوال الخادم في `src/lib/storefront-leads.functions.ts`
  (`createBackInStockRequest`, `subscribeToNewsletter`) التي تعمل بصلاحية service role وتطبّق:
  - حدّاً منزلقاً لكل عنوان IP (5/ساعة) ولكل براند (200/ساعة) — نفس نمط `api.admin.nabda-otp.ts`.
  - تحققاً من أن المنتج (والمتغيّر) يتبع البراند، وأن البراند نشط.
  - تطبيعاً للتواصل (أرقام فقط للواتساب، بريد صغير الأحرف) ومنع التكرار.
- `sessionStorage` في النماذج مجرد تلميح لتجربة المستخدم (يمنع إعادة الإرسال العرضية) وليس آلية حماية.
- الحقول القابلة للتبديل من التاجر: `back_in_stock_enabled`, `newsletter_enabled` في
  **الإعدادات ← المتجر ← خيارات المظهر الجديد**.
